Build each client and tell it where the server is.

Where clients look

클라이언트가 찾는 곳

Android, iOS and desktop default to 127.0.0.1:23100. Override with GEMSTONE_SERVER_HOST and GEMSTONE_SERVER_PORT (environment variable or JVM system property). The port value includes its colon: :23100.

Android, iOS, 데스크톱의 기본값은 127.0.0.1:23100 입니다. GEMSTONE_SERVER_HOST 와 GEMSTONE_SERVER_PORT(환경 변수 또는 JVM 시스템 속성)로 바꿉니다. 포트 값에는 콜론이 포함됩니다: :23100.

Desktop

데스크톱

./gradlew :app:run
./gradlew :app:packageDistributionForCurrentOS   # Dmg, Msi or Deb

The desktop app accepts the server on its command line:

데스크톱 앱은 명령줄에서 서버를 받습니다:

--server 192.168.0.10:23100        # or -s
--host 192.168.0.10 --port 23100   # or -h / -p
--help

Android

Android

./gradlew :app:installDebug
adb reverse tcp:23100 tcp:23100   # make the device's 127.0.0.1:23100 reach your machine

The Android client has no address setting yet, so adb reverse is the simplest way to reach a server on your computer from a phone or an emulator.

Android 클라이언트에는 아직 주소 설정이 없으므로, 휴대폰이나 에뮬레이터에서 내 컴퓨터의 서버로 가는 가장 간단한 방법은 adb reverse 입니다.

Web

웹

The web client talks to whichever host served it, so it must be served by the Gemstone server — that is what http://127.0.0.1:23100/ does. The bundle lives in api/src/main/webpack/. To refresh it after changing the client:

웹 클라이언트는 자신을 서빙한 호스트와 대화하므로, Gemstone 서버가 서빙해야 합니다 — http://127.0.0.1:23100/ 이 바로 그것입니다. 번들은 api/src/main/webpack/ 에 있습니다. 클라이언트를 고친 뒤 갱신하려면:

./gradlew :app:wasmJsBrowserDistribution
# then copy the production distribution into api/src/main/webpack/

./gradlew :app:wasmJsBrowserDevelopmentRun is handy for UI work, but its page is served by the Gradle dev server, which has no chat API behind it.

./gradlew :app:wasmJsBrowserDevelopmentRun 은 UI 작업에 편리하지만, 그 페이지는 Gradle 개발 서버가 서빙하므로 뒤에 채팅 API 가 없습니다.

iOS

iOS

Open app/src/iosMain/swift/iosApp.xcodeproj in Xcode. Status: partial — the project's build phase still calls :composeApp:embedAndSignAppleFrameworkForXcode from the wrong directory; it needs to run ./gradlew :app:embedAndSignAppleFrameworkForXcode from the repository root before an Xcode build can succeed.

Xcode 에서 app/src/iosMain/swift/iosApp.xcodeproj 를 엽니다. 상태: 부분 — 프로젝트의 빌드 단계가 아직 잘못된 디렉터리에서 :composeApp:embedAndSignAppleFrameworkForXcode 를 부릅니다. Xcode 빌드가 성공하려면 저장소 루트에서 ./gradlew :app:embedAndSignAppleFrameworkForXcode 를 실행하도록 고쳐야 합니다.
