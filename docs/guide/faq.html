Questions질문

Does Gemstone work offline?Gemstone 은 오프라인으로 동작하나요?

Not yet. Today every chat goes through the Python server, which can run on your own machine without internet — except for the tools that look things up online. Fully offline, in-app inference is the goal.

아직은 아닙니다. 지금은 모든 채팅이 Python 서버를 거치고, 그 서버는 인터넷 없이 내 머신에서 돌 수 있습니다 — 온라인 조회를 하는 도구만 빼고요. 완전한 오프라인, 앱 내 추론이 목표입니다.

Where are my chats stored?대화는 어디에 저장되나요?

In the client's memory, for as long as it runs. The client writes nothing to disk and sends nothing anywhere except your server — which, note, prints prompts and answers to its console.

실행되는 동안 클라이언트의 메모리에만 있습니다. 클라이언트는 디스크에 쓰지 않고 내 서버 말고는 어디에도 보내지 않습니다 — 다만 서버는 프롬프트와 답변을 콘솔에 출력합니다.

What hardware do I need?어떤 하드웨어가 필요한가요?

No GPU is needed. The default model, Qwen 3 0.6B, is small enough to run on a CPU.

GPU 는 필요 없습니다. 기본 모델인 Qwen 3 0.6B 는 작아서 CPU 에서 돌아갑니다.

Can I use OpenAI or Anthropic models?OpenAI 나 Anthropic 모델을 쓸 수 있나요?

No. Gemstone runs open-weight models locally. Whether remote providers belong in the project at all is an open question for the maintainers.

아니요. Gemstone 은 공개 가중치 모델을 로컬에서 돌립니다. 원격 제공자가 이 프로젝트에 들어올지 자체가 메인테이너의 열린 질문입니다.

Contributing기여하기

Gemstone runs on intent → spec → test → code:

Gemstone 은 의도 → 스펙 → 테스트 → 코드 로 운영합니다:

  1. The intent says what the project is for. A change outside it starts as a conversation, not a pull request.
  2. 의도는 프로젝트가 무엇을 위한 것인지 말합니다. 그 밖의 변경은 풀 리퀘스트가 아니라 대화로 시작합니다.
  3. A behaviour change first updates the spec, with a status: implemented, partial or planned.
  4. 동작 변경은 먼저 스펙을 상태(구현 · 부분 · 예정)와 함께 갱신합니다.
  5. Write the test from the spec and watch it fail before you write the code.
  6. 스펙에서 테스트를 쓰고, 코드를 쓰기 전에 실패하는 것을 확인합니다.
  7. Make it pass. Use LF line endings, and keep each pull request to one concern.
  8. 통과시킵니다. 줄바꿈은 LF 로, 풀 리퀘스트 하나에는 관심사 하나만.

The intent and spec live on the develop branch: INTENT · SPEC. Report bugs and propose ideas in issues.

의도와 스펙은 develop 브랜치에 있습니다: INTENT · SPEC. 버그와 제안은 이슈로 남겨 주세요.
